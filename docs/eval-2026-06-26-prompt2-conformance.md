## 1. 核心结论

| 指标 | Qwen3-32B 旧→新 | deepseek_v4 旧→新 |

| ✓ 符合 | 9 (24%) → **20 (53%)** | 17 (45%) → **26 (68%)** |

**两个模型符合率都大幅提升**：Qwen3 +29 分（截断消除）、v4 +23 分（保守兜底消除 13→4）。**v4 仍更准（68% vs 53%）**，答得更完整、引用规范（`[^n]` + 文末「参考文件」）。

旧 prompt 的两大病灶被治好：
- **Qwen3 截断**（旧：中位 31 字、60% 半截话）→ `max_tokens=1024` 恢复后中位 184 字，截断消失。
- **v4 过度兜底**（旧：13 题「无相关内容」）→ 新 prompt「只要检索足以支持就正常作答，绝不误报未找到」把兜底压到 4 题。

## 3. 检索 / 重排耗时（与模型无关，每题一致）

来源：`retrieve_trace` / `rerank_trace`（38 题聚合）

| 阶段 | avg | p50 | max |
|---|---|---|---|
| 检索 embed（bge-m3，1 条 query） | 116 ms | 109 | 188 |
| 检索 search（Milvus 6 库并行） | 240 ms | 288 | 801 |
| **检索 total** | **357 ms** | 400 | 946 |
| **重排（embed_rerank）** | **428 ms** | 408 | 780 |

- 检索固定召回 60 条（top_k=10 × 6 库），重排 60 候选全排。
- 检索+重排合计 ~785 ms，占单次总耗时（~28–30s）很小——**生成（LLM）是绝对瓶颈**。
- 重排在多题中确实改变了顺序（如 q6 检索 top3 是 policy_group，重排把 `数字交通十四五规划` 提到首位，答案正基于它）——重排有价值。

## 4. 残留问题与建议

1. **q32 / q33 双双兜底**（平台卡顿、成果录入用不了）—— 参考答案有内容，是**检索盲区**（召回不到相关 chunk），与 prompt 无关。需补 KB 元数据或调检索（如关键词兜底、扩 chunk）。
2. **q35 v4 判错**（说「不能过」，参考是「允许差异填报、审核定夺」）—— 唯一 ✗；v4 对「能否通过」类问题偏绝对，可在 prompt 里加「审核类问题留余地」。
3. **q10 Qwen3 空答案**（1 次）—— 疑似单次生成异常（未命中 finish），重跑大概率恢复；非系统性。
4. **v4 仍兜底 q2 / q30**（Qwen3 能答）—— v4 检索阈值/上下文利用率偏严，可在 prompt 强化「检索有部分相关即作答」。
5. **q26–q28**（待办点不动类）两模型都只给 2/4 原因，漏了关键的「非正常流程→在科技项目模块搜索【处理】」—— 该答案在 KB 里但召回靠后，可调 top_n 或在 chunker 里强化操作步骤段。

---

## 5. 结论

科小星 v2 prompt + max_tokens 修复是**显著正向**：两模型符合率从 24%/45% 提升到 53%/68%，截断与误报兜底两大痼疾消除。**v4 综合更优（68%、答得更完整、引用规范）**，建议生产用 v4；Qwen3 作为备选（53%，但单题 q10 偶发空答需重试机制兜底，已具备）。剩余提升空间主要在**检索召回**（q32/33 等盲区）而非 prompt。
